# Zadania - Bezpieczeństwo w aplikacjach webowych - hasła, JWT, sesje i ciasteczka

Zadania oparte wyłącznie na `9-bezpieczenstwo-jwt.md` oraz wiedzy z lekcji 1-8 (architektura routes/controllers/models, `mysql2/promise`). Nie potrzebujesz jeszcze centralnego middleware błędów ani CORS - to temat kolejnej lekcji.

Potrzebujesz działającego API użytkowników z lekcji 8 (tabela `users`, warstwy routes/controllers/models) oraz zainstalowanych pakietów `bcrypt` i `jsonwebtoken`.

## Zadanie 1 - rejestracja z hashowaniem hasła

Dodaj do istniejącego API endpoint `POST /api/auth/register`. Kontroler ma sprawdzić, czy podano `name`, `email` i `password` (400, jeśli czegoś brakuje), zahashować hasło przez `bcrypt.hash` i zapisać nowego użytkownika w bazie. Odpowiedź nie może zawierać hasła ani jego hasha.

## Zadanie 2 - rejestracja z zajętym adresem e-mail

Rozbuduj endpoint z zadania 1: przed zapisaniem nowego użytkownika sprawdź w bazie, czy e-mail nie jest już zajęty. Jeśli jest, zwróć `409` (konflikt) z komunikatem "Użytkownik z takim adresem e-mail już istnieje". Zastanów się, jakiego zapytania SQL potrzebujesz do tego sprawdzenia.

## Zadanie 3 - logowanie i token

Dodaj endpoint `POST /api/auth/login`. Po poprawnej weryfikacji hasła (`bcrypt.compare`) wystaw token JWT zawierający `id` i `email` użytkownika, ważny 1 godzinę, i zwróć go w odpowiedzi jako `{ token }`.

## Zadanie 4 - middleware chroniący zapis, nie tylko odczyt

W lekcji middleware `requireAuth` chronił odczyt profilu. Zabezpiecz nim teraz endpoint `POST /api/books` (albo inny zasób z Twojego API z lekcji 8) tak, żeby dodawać nowe rekordy mógł wyłącznie zalogowany użytkownik. Sprawdź, że próba dodania bez tokenu kończy się `401`.

## Zadanie 5 - token w ciasteczku

Zmień endpoint logowania tak, żeby zamiast zwracać token w JSON-ie, zapisywał go w ciasteczku (`res.cookie`) z opcją `httpOnly` i czasem życia 1 godziny. Dostosuj middleware `requireAuth` tak, żeby odczytywał token z `req.cookies.token` zamiast z nagłówka `Authorization`. Pamiętaj o `cookie-parser`.

## Zadanie 6 - znajdź błędy bezpieczeństwa

W poniższym kodzie są trzy niezależne błędy związane z tym, co poznałeś w tej lekcji. Znajdź je i popraw:

```javascript
const jwt = require("jsonwebtoken");

async function register(req, res) {
    const { name, email, password } = req.body;

    const newUser = await userModel.createUser(name, email, password);

    const token = jwt.sign(
        { id: newUser.id, email: newUser.email },
        "sekret123",
        { expiresIn: "1h" }
    );

    res.status(201).json({ user: newUser, token });
}
```

## Zadanie 7 - sesje kontra JWT w praktyce

Dla każdego z poniższych scenariuszy zdecyduj jednym zdaniem, czy lepiej pasuje do niego sesja czy JWT, i uzasadnij wybór:

1. Panel administracyjny działający wyłącznie na jednym serwerze firmy.
2. Publiczne API, z którego korzysta zarówno aplikacja mobilna, jak i strony napisane przez inne firmy.
3. Aplikacja, w której administrator musi mieć możliwość natychmiastowego wylogowania podejrzanego konta.

## Jak sprawdzić rozwiązania

Testuj rejestrację i logowanie w Postmanie/Insomni z różnymi danymi (poprawne, zajęty e-mail, złe hasło, brakujące pole). Po zalogowaniu skopiuj token i wklej go na jwt.io, żeby zobaczyć, jakie dane faktycznie przenosi - to dobry sposób, żeby upewnić się, że nie umieściłeś w nim niczego wrażliwego.
