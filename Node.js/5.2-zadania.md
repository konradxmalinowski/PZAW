# Zadania - Routing zaawansowany i middleware w Express.js

Zadania oparte wyłącznie na `5-express-routing-middleware.md` oraz wiedzy z lekcji 1-4. Do rozwiązania wystarczy Express, `req.params`, `express.Router()` i własne middleware - nie potrzebujesz bazy danych, EJS ani JWT.

## Zadanie 1 - biblioteka po id

Masz w pamięci tablicę książek:

```javascript
const books = [
    { id: 1, title: "Lalka", author: "Bolesław Prus" },
    { id: 2, title: "Ferdydurke", author: "Witold Gombrowicz" },
    { id: 3, title: "Solaris", author: "Stanisław Lem" }
];
```

Napisz trasę `GET /api/books/:id`, która zwraca jedną książkę na podstawie `id` z adresu, a jeśli książka o takim `id` nie istnieje - zwraca kod `404` z komunikatem w JSON.

Wskazówka: `req.params.id` jest stringiem, więc przy porównaniu z `id` w tablicy zamień go przez `Number()`.

## Zadanie 2 - dwa parametry w ścieżce

Do biblioteki z zadania 1 dodaj każdej książce tablicę recenzji, np. `reviews: [{ id: 1, text: "Świetna" }, { id: 2, text: "Średnia" }]`. Napisz trasę `GET /api/books/:bookId/reviews/:reviewId`, która zwraca konkretną recenzję konkretnej książki. Obsłuż przypadek, gdy nie istnieje książka, oraz osobno przypadek, gdy książka istnieje, ale nie ma takiej recenzji.

## Zadanie 3 - router w osobnym pliku

Przenieś wszystkie trasy dotyczące książek z zadań 1-2 do osobnego pliku `routes/books.js`, korzystając z `express.Router()`. W głównym pliku `server.js` podepnij ten router pod ścieżką bazową `/api/books`. Sprawdź, że po zmianie wszystko nadal działa pod tymi samymi adresami co wcześniej.

## Zadanie 4 - middleware logujący czas

Napisz middleware `requestTime`, które do obiektu `req` dopisuje nową właściwość `req.requestTime` z aktualną datą i godziną (`new Date()`), a następnie wywołuje `next()`. Podepnij je globalnie przez `app.use()`. W dowolnej trasie wypisz `req.requestTime` w konsoli, żeby sprawdzić, że middleware faktycznie zdążyło ustawić tę wartość, zanim trasa zaczęła działać.

## Zadanie 5 - prosty strażnik z kluczem API

Napisz middleware `checkApiKey`, które sprawdza, czy w nagłówkach żądania (`req.headers`) znajduje się nagłówek `x-api-key` o ustalonej z góry wartości (np. `"tajny-klucz"`). Jeśli nagłówka brakuje albo ma złą wartość - middleware ma zwrócić kod `401` z komunikatem. Podepnij to middleware wyłącznie pod trasę `DELETE /api/books/:id` - reszta tras ma działać bez tego wymogu.

To nie jest jeszcze prawdziwa autoryzacja użytkowników (to osobny, dalszy temat) - tu chodzi wyłącznie o przećwiczenie mechanizmu middleware jako bramki przed trasą.

## Zadanie 6 - walidacja przy dodawaniu zasobu

Napisz middleware `validateBook`, które sprawdza, czy `req.body` zawiera pola `title` i `author`. Jeśli któregoś brakuje - zwróć kod `400` z czytelnym komunikatem, które pole jest wymagane. Podepnij je pod trasę `POST /api/books` w routerze z zadania 3.

## Zadanie 7 - znajdź błąd

Poniższy middleware ma logować każde żądanie i przepuszczać je dalej, ale coś jest z nim nie tak - żądania do serwera nigdy się nie kończą:

```javascript
function requestLogger(req, res, next) {
    console.log(`${req.method} ${req.url}`);
}

app.use(requestLogger);
```

Znajdź błąd, napraw go i krótko (jednym zdaniem) zapisz w komentarzu, co dokładnie się działo, zanim naprawiłeś kod.

## Zadanie 8 - kolejność ma znaczenie

Masz middleware `checkApiKey` z zadania 5 i trasę `DELETE /api/books/:id`. Zarejestruj je w złej kolejności - najpierw trasę, a middleware dopiero po niej - i sprawdź w praktyce, co się stanie przy żądaniu bez nagłówka `x-api-key`. Zapisz jednym zdaniem obserwację, dlaczego middleware w takiej kolejności nie chroni trasy, a następnie popraw kolejność na właściwą.

## Jak sprawdzić rozwiązania

Do testowania endpointów użyj Postmana, Insomni albo `curl`. Sprawdzaj nie tylko przypadek "wszystko poprawne", ale też przypadki brzegowe: nieistniejące `id`, brakujące pole w `req.body`, brak wymaganego nagłówka. Jeśli middleware ma zwracać błąd, upewnij się, że w tym przypadku dalsza część kodu (właściwa trasa) faktycznie się nie wykonuje.
