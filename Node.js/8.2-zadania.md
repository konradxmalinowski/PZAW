# Zadania - Projektowanie REST API - operacje CRUD i endpointy do uploadu plików

Zadania oparte wyłącznie na `8-rest-api-crud-upload.md` oraz wiedzy z lekcji 1-7 (Express, routing, `req.params`, `mysql2/promise`). Nie potrzebujesz jeszcze haseł, JWT ani żadnej autoryzacji - to temat kolejnej lekcji.

Potrzebujesz działającej bazy MySQL/MariaDB i projektu Express z modułem `mysql2/promise` skonfigurowanym tak jak w lekcji 7.

## Zadanie 1 - projekt API na papierze

Zanim napiszesz kod, zaprojektuj REST API dla zasobu `books` (książki: `id`, `title`, `author`, `year`). Zapisz w punktach, jaki adres i metoda HTTP odpowiadają za: listę wszystkich książek, jedną książkę po id, dodanie nowej książki, aktualizację książki, usunięcie książki. Trzymaj się konwencji z lekcji (rzeczownik w liczbie mnogiej, bez czasownika w adresie).

## Zadanie 2 - warstwa model

Utwórz tabelę `books` (DDL, czyli polecenie `CREATE TABLE` tworzące strukturę tabeli w bazie) i napisz `models/bookModel.js` z funkcjami `getAllBooks()`, `getBookById(id)`, `createBook(title, author, year)`, `updateBook(id, title, author, year)`, `deleteBook(id)` - dokładnie w stylu z `userModel.js` z lekcji (przygotowane zapytania, `?` zamiast sklejania stringów).

## Zadanie 3 - warstwa controller i route

Napisz `controllers/booksController.js` i `routes/books.js` korzystające z modelu z zadania 2, i podepnij je w `server.js` pod adresem `/api/books`. Każda funkcja kontrolera ma być opakowana w `try/catch` z kodem `500` przy błędzie.

## Zadanie 4 - spójna obsługa błędów

Dodaj do kontrolera z zadania 3: `404` gdy książka o podanym `id` nie istnieje (dla GET jednej, PUT, DELETE), `400` gdy przy dodawaniu brakuje `title` albo `author`. Sprawdź działanie każdego przypadku osobno (Postman/Insomnia/`curl`).

## Zadanie 5 - upload okładki

Dodaj endpoint `POST /api/books/:id/cover`, który przez `multer` przyjmuje jeden plik pod nazwą pola `cover`, zapisuje go w katalogu `uploads/` i zwraca w odpowiedzi JSON nazwę zapisanego pliku. Jeśli plik nie zostanie przesłany, endpoint ma zwrócić `400`.

## Zadanie 6 - plan testów

Dla endpointu `POST /api/books` z zadania 3 opisz (bez pisania kodu, samym tekstem) co najmniej trzy żądania testowe do wykonania w Postmanie: z poprawnymi danymi, z brakującym `title`, oraz z pustym body. Dla każdego zapisz, jakiego kodu statusu i jakiej odpowiedzi się spodziewasz.

## Zadanie 7 - znajdź błąd (logika w routerze)

Poniższy kod działa, ale łamie zasadę podziału na warstwy z tej lekcji:

```javascript
const express = require("express");
const router = express.Router();
const pool = require("../db");

router.get("/", async (req, res) => {
    try {
        const [rows] = await pool.query("SELECT * FROM books");
        res.json(rows);
    } catch (error) {
        res.status(500).json({ message: "Błąd serwera" });
    }
});

module.exports = router;
```

Przenieś zapytanie SQL do `models/bookModel.js`, a obsługę `req`/`res` do `controllers/booksController.js`, tak żeby `routes/books.js` zawierał wyłącznie mapowanie adresu na funkcję kontrolera.

## Jak sprawdzić rozwiązania

Testuj każdy endpoint osobno w Postmanie/Insomni - nie tylko przypadek poprawny, ale też błędne id, brakujące pola i (dla uploadu) brak pliku. Po każdej operacji modyfikującej dane sprawdź stan tabeli osobnym zapytaniem `SELECT`.
