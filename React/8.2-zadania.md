# Zadania - Stan globalny aplikacji - Context API i problem prop drillingu

Zadania do pliku `8-context-api.md`. Potrzebujesz tylko tego, co tam jest - prop drilling, `createContext`, `Provider`, `useContext`, własny hook opakowujący.

## Zadanie 1 - zbuduj prop drilling

Zbuduj drzewo komponentów `App` → `Layout` → `Sidebar` → `UserInfo`, gdzie `App` trzyma obiekt danych użytkownika (np. `{ name: "Ania", role: "uczeń" }`) i przekazuje go przez props przez `Layout` i `Sidebar`, aż do `UserInfo`, który jako jedyny go wyświetla. `Layout` i `Sidebar` mają przyjmować ten prop tylko po to, żeby oddać go dalej - to ma być świadomie napisany przykład prop drillingu.

## Zadanie 2 - zamiana na Context

Przerób aplikację z zadania 1 tak, żeby `Layout` i `Sidebar` w ogóle nie wiedziały o danych użytkownika. Stwórz `UserContext` przez `createContext`, opakuj `App` w `UserContext.Provider` z wartością `user`, i odczytaj dane bezpośrednio w `UserInfo` przez `useContext`.

Wskazówka: po tej zmianie `Layout` i `Sidebar` nie powinny mieć w ogóle propsa związanego z użytkownikiem.

## Zadanie 3 - własny hook

Napisz własny hook `useUser()`, który opakowuje `useContext(UserContext)`. Zamień w `UserInfo` bezpośrednie wywołanie `useContext(UserContext)` na `useUser()`.

## Zadanie 4 - motyw UI

Zbuduj `ThemeContext` z `ThemeProvider` trzymającym stan `theme` (`"light"`/`"dark"`) i funkcję `toggleTheme`. Dodaj przycisk w dowolnym miejscu aplikacji (niekoniecznie blisko `App`), który po kliknięciu przełącza motyw, oraz komponent, który wyświetla aktualny motyw tekstem - obydwa powinny korzystać z kontekstu przez własny hook `useTheme()`.

## Zadanie 5 - znajdź błąd (brak Providera)

Poniższy kod wyrzuca błąd przy próbie odczytania `user.name`:

```javascript
function App() {
    return <UserBadge />;
}

function UserBadge() {
    const user = useUser();
    return <p>Zalogowany: {user.name}</p>;
}
```

`UserContext` został utworzony przez `createContext(null)`, a `useUser` to zwykłe opakowanie `useContext(UserContext)`. Znajdź przyczynę błędu i popraw kod.

## Zadanie 6 - props czy Context

Dla każdego z poniższych trzech scenariuszy zdecyduj, czy lepiej użyć zwykłych props, czy Context API, i krótko uzasadnij (1-2 zdania):

1. Komponent `Card` dostaje od rodzica tytuł i cenę produktu do wyświetlenia.
2. Informacja o zalogowanym użytkowniku jest potrzebna w komponentach `Navbar`, `Sidebar`, `ProfilePage` i `CommentForm`, rozrzuconych w różnych miejscach drzewa.
3. Komponent `Modal` dostaje od rodzica funkcję `onClose`, wywoływaną po kliknięciu przycisku zamknięcia.

## Jak sprawdzić rozwiązania

Uruchom aplikację (`npm run dev`) i sprawdź w React DevTools (zakładka Components), że po zmianie na Context komponenty pośrednie (`Layout`, `Sidebar`) rzeczywiście nie mają już propsa z danymi użytkownika, a mimo to `UserInfo` nadal poprawnie je wyświetla.
