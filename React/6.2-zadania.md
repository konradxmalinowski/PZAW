# Zadania - Komunikacja z backendem - fetch, wysyłanie plików, odbiór danych i integracja z API

Zadania dotyczą wyłącznie tego, co jest w pliku `6-fetch-useeffect.md`: `useEffect` z pustą tablicą zależności, `fetch` (warianty `.then()` i `async/await`), stany `loading`/`error`/dane, `res.ok`, oraz wysyłanie danych metodą `POST`. Do żądań możesz użyć dowolnego przykładowego adresu API (np. `http://localhost:3000/api/produkty`) - nie musi realnie działać, ważne jest poprawne napisanie komponentu.

## 1. Lista przy starcie

Napisz komponent `UserList`, który przy pierwszym renderze pobiera listę użytkowników z `http://localhost:3000/api/users` i wyświetla ich imiona jako listę `<li>`. Użyj wariantu z `async/await` wewnątrz `useEffect`.

Wskazówka: pamiętaj o tablicy zależności `[]` - bez niej żądanie poleci w nieskończoną pętlę.

## 2. Loader

Rozbuduj komponent z zadania 1 o stan `loading` (start: `true`). Zanim dane dotrą, komponent ma wyświetlać `<p>Ładowanie...</p>` zamiast pustej listy.

Wskazówka: `loading` ustawiasz na `false` dopiero, gdy żądanie się zakończy - najwygodniej w bloku `finally`.

## 3. Obsługa błędu

Do tego samego komponentu dodaj stan `error`. Sprawdź `res.ok` - jeśli serwer odpowiedział błędem, rzuć wyjątek (`throw new Error(...)`) i złap go w `catch`, zapisując czytelny komunikat w stanie `error`. Wypróbuj to, celowo wpisując zły adres URL (np. z literówką) i sprawdzając, czy komunikat błędu faktycznie się pojawia zamiast pustego ekranu.

## 4. Znajdź błąd - pętla żądań

Poniższy komponent wysyła żądania do serwera bez przerwy, dopóki karta przeglądarki jest otwarta. Znajdź przyczynę i popraw kod.

```javascript
function ProductList() {
    const [products, setProducts] = useState([]);

    useEffect(() => {
        fetch("http://localhost:3000/api/produkty")
            .then((res) => res.json())
            .then((data) => setProducts(data));
    });

    return (
        <ul>
            {products.map((p) => (
                <li key={p.id}>{p.name}</li>
            ))}
        </ul>
    );
}
```

## 5. Znajdź błąd - async w useEffect

Poniższy kod w ogóle nie działa (React zgłasza ostrzeżenie w konsoli). Znajdź przyczynę i przepisz go poprawnie.

```javascript
useEffect(async () => {
    const res = await fetch("http://localhost:3000/api/produkty");
    const data = await res.json();
    setProducts(data);
}, []);
```

## 6. Wysyłanie danych przez POST

Nawiązując do formularza z poprzedniej lekcji, napisz funkcję `addTask(title)`, która wysyła nowe zadanie metodą `POST` na adres `http://localhost:3000/api/tasks`, z odpowiednim nagłówkiem `Content-Type` i treścią zamienioną przez `JSON.stringify`. Funkcja ma zwrócić dane nowo utworzonego zadania (odpowiedź serwera po `res.json()`).

## 7. Lista + dodawanie w jednym komponencie

Połącz zadania 1-6 w jeden komponent `TaskList`: przy starcie pobiera listę zadań z API i ją renderuje (z loaderem i obsługą błędu), a pod listą ma prosty formularz kontrolowany (jedno pole tekstowe + przycisk) dodający nowe zadanie przez `POST`. Po udanym dodaniu nowe zadanie ma pojawić się na liście bez ponownego pobierania całości z serwera - dołóż je do istniejącej tablicy w stanie.

Wskazówka: to ten sam wzorzec niemutowalnej aktualizacji tablicy, co w lekcji o `useState` - `setTasks([...tasks, newTask])`.

## 8. Refaktoryzacja - wydzielona funkcja

Weź dowolny komponent z poprzednich zadań, w którym logika pobierania danych jest zapisana bezpośrednio wewnątrz `useEffect`, i wydziel ją do osobnej, nazwanej funkcji `async` zdefiniowanej poza `useEffect` (np. `fetchProducts()`), którą `useEffect` jedynie wywołuje. Zastanów się, czy taki podział poprawia czytelność komponentu.

## Jak sprawdzić rozwiązanie

Otwórz zakładkę Network w narzędziach deweloperskich przeglądarki - powinieneś zobaczyć dokładnie jedno żądanie przy starcie komponentu (nie dziesiątki w ciągu sekundy) oraz jedno dodatkowe żądanie POST przy każdym dodaniu elementu. Jeśli licznik żądań w zakładce Network rośnie bez końca, to znak, że tablica zależności w `useEffect` jest źle ustawiona.
