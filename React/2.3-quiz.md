# Quiz - Komponenty funkcyjne, props i kompozycja interfejsu

20 pytań jednokrotnego wyboru do pliku `2-komponenty-props.md`. Wybierz jedną odpowiedź, a na końcu sprawdź się z sekcją "Odpowiedzi".

**1. Czym jest komponent funkcyjny w React?**

A. Specjalną klasą wbudowaną w Reacta
B. Zwykłą funkcją JavaScript, która zwraca JSX
C. Plikiem konfiguracyjnym Vite
D. Funkcją, która musi zawsze zwracać `null`

**2. Czym są props?**

A. Zmiennymi globalnymi dostępnymi w każdym komponencie
B. Danymi przekazywanymi do komponentu z miejsca, w którym go użyto
C. Metodami do modyfikowania stanu komponentu
D. Plikami CSS dołączanymi do komponentu

**3. Jak przekazuje się string jako props w JSX?**

A. `<Card title={"Klawiatura"} />` wyłącznie w klamrach
B. `<Card title="Klawiatura" />` w cudzysłowie
C. `<Card title=Klawiatura />` bez żadnego ograniczenia
D. `<Card>title=Klawiatura</Card>`

**4. Jak przekazuje się liczbę jako props w JSX?**

A. `<Card price="249" />`
B. `<Card price=(249) />`
C. `<Card price={249} />`
D. Liczb nie można przekazywać przez props

**5. Co trafia do parametru funkcji komponentu, gdy nie stosujemy destrukturyzacji?**

A. Tablica wszystkich propsów
B. Jeden obiekt zawierający wszystkie przekazane propsy
C. Osobna zmienna dla każdego propsa
D. `undefined`, dopóki nie zaimportujemy `props`

**6. Który zapis to poprawna destrukturyzacja propsów w parametrach funkcji?**

A. `function Card(props.title, props.price)`
B. `function Card([title, price])`
C. `function Card({ title, price })`
D. `function Card(title, price)`

**7. Co zwróci poniższy komponent, wywołany jako `<Card title="Mysz" price={99} />`?**
```javascript
function Card({ title, price }) {
    return <p>{title} - {price} zł</p>;
}
```

A. `title - price zł`
B. `Mysz - 99 zł`
C. Błąd, bo brakuje `props.`
D. `{title} - {price} zł` jako zwykły tekst

**8. Dlaczego destrukturyzacja propsów jest preferowana w praktyce?**

A. Bo `props.x` w ogóle nie działa w nowszych wersjach Reacta
B. Bo jest krótsza i od razu pokazuje, jakich propsów komponent oczekuje
C. Bo jest jedynym sposobem przekazania liczby jako propsa
D. Bo pozwala pominąć `export default`

**9. Jaki typ danych NIE może zostać przekazany przez props?**

A. Funkcja
B. Obiekt
C. Boolean
D. Każdy z powyższych może zostać przekazany przez props

**10. Co się stanie po wykonaniu poniższego kodu?**
```javascript

    cena = cena - 10;
    return <p>{cena}</p>;
}
```

A. Kod zgłosi błąd kompilacji
B. Zadziała technicznie, ale jest to złamanie zasady "props tylko do odczytu"
C. React automatycznie zablokuje tę linijkę
D. `cena` stanie się `undefined`

**11. Jaka jest poprawna, zgodna z Reactem wersja poprzedniego przykładu?**

A. `const cena2 = cena - 10;` i zwrócenie `cena2`
B. Zostawienie kodu bez zmian - jest poprawny
C. Usunięcie propsa `cena` z komponentu
D. Zmiana `cena` na `let cena` w miejscu wywołania komponentu

**12. Co oznacza zasada "dane płyną w jedną stronę" w React?**

A. Komponent potomny może swobodnie zmieniać propsy rodzica

C. Dane muszą zawsze pochodzić z API
D. Zasada dotyczy wyłącznie `useState`, nie propsów

**13. Który komponent poprawnie przyjmuje funkcję jako props i podpina ją pod zdarzenie kliknięcia?**

A. `function Button({ onClick }) { return <button onClick={onClick}>OK</button>; }`
B. `function Button({ onClick }) { return <button onClick="onClick">OK</button>; }`
C. `function Button(onClick) { return <button onClick={onClick}>OK</button>; }`
D. `function Button({ onClick }) { return <button click={onClick}>OK</button>; }`

**14. Dlaczego `Button` z poprzedniego pytania nie musi wiedzieć, co dokładnie robi funkcja `onClick`?**

A. Bo React sam decyduje, jaką logikę wykonać

**15. Czym jest kompozycja komponentów?**

**16. W poniższym kodzie `App` renderuje trzy komponenty `Card` z różnymi danymi. Ile razy zostanie wykonana funkcja `Card`?**

```javascript
<Card title="B" />
<Card title="C" />
```

B. Trzy razy, raz dla każdego użycia

D. Zależy od liczby propsów

**17. Dlaczego poniższy kod nie zadziała zgodnie z intencją?**
